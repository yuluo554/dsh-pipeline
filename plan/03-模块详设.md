# 模块详设（plan/03）

> 目录约定：`src/`（host 半）、`client/`（web 半，P1 起）、`data/`（fixtures，见 plan/04）。签名在实现时可微调，改动需回写本文件。

## host 半模块

### schema.ts — 定义校验（FR-1）
```ts
export interface PipelineDef {
  name: string; description: string
  nodes: PipelineNode[]
  options?: { maxAgentsPerNode?: number; defaultFailurePolicy?: 'abort'|'skip' }
}
export interface PipelineNode {
  id: string; label?: string
  prompts: string[]                       // ≥1 条，节点内按序投递
  model?: { provider?: string; model?: string; reasoningEffort?: string }
  skills?: string[]; tools?: { allow?: string[]; deny?: string[] }
  dependsOn?: string[]                    // 缺省 = 线性串接前一个
  outputSchema?: JSONSchema; failurePolicy?: 'abort'|'skip'; retry?: number
}
export function validateDef(raw: unknown): { ok: true; def: PipelineDef } | { ok: false; errors: DefError[] }
```
- 测试点：合法/非法矩阵（B2 基准）；错误信息可读（含 JSON 指针路径）。

### ir.ts — 规范化中间表示（对应方法论"统一中间表示"）
- 输入 `PipelineDef` → 输出有序执行图（线性化节点序列 + 每节点解析后的模板变量依赖表）。
- 规则优先、确定性：拓扑排序（Kahn）、环检测、未知 `{{var}}` 静态拒绝、`dependsOn` 显式覆盖隐式串接。
- 测试点：环依赖/自依赖/重复 id/未知变量 → 明确错误；线性化顺序稳定（同输入同输出）。

### compiler.ts — IR → 脚本（FR-2，核心资产）
- `compile(ir: PipelineIR): string` —— 生成普通 JS workflow 脚本；模板注入用 JSON 安全拼接（`JSON.stringify` 值插值），**禁止 eval/Function**。
- 节点内多 prompt：`for` 循环顺序 `await agent({...})`，前次输出按变量名并入下一次 prompt 上下文。
- 测试点：B1 快照基准（固定 fixtures → 固定脚本字符串）；生成脚本过语法检查（`new Function` 仅用于语法校验，不执行——或用 acorn 解析）。

### runner.ts — 唯一官方 API 触点（FR-3/6/8/12）
```ts
export interface RunOutcome { value: unknown; stopReason: string; error?: string; agentsStarted: number }
export async function runPipeline(deps: { engine: WorkflowEngine; caps: SubagentCapabilities; parent: Agent; signal?: AbortSignal },
                                  name: string, input: string, opts?: RunOpts): Promise<RunOutcome>
```
- 职责：能力探测（caps 缺 flag → 降级/报错）→ `engine.start({ script, meta, args, subagentProvider: 'spawn-in-process', maxTotalAgents, parent, signal })` → `await run.result` → 失败策略执行（abort 直接上抛；skip 映射节点输出为 null 并继续；retry 在脚本内循环）→ 统一 `RunOutcome`。
- 失败策略、retry 循环都**编译进脚本**，runner 只组装——保证与引擎语义一致。

### store.ts — 定义存取（FR-1）
- `listDefs(ctx) / loadDef(ctx, name) / saveDef(ctx, def)`，路径 `工作区/.dsh/pipelines/<name>.json`，写前原子替换（temp+rename）。
- 测试点：并发写、坏 JSON、重名。

### entry.ts — 入口注册（FR-4/5）
- `/pipeline list|run|show` 命令（`ctx.commands`，不经模型轮次）。
- `pipeline` 模型工具（`ctx.tools.register(defineTool(...))`）：参数 `{ name, input }`，返回 `RunOutcome` 摘要；工具描述声明"固定流程重复任务"场景（供模型路由）。
- 全部注册为 Cordis effect，随插件卸载撤销。

## client 半模块（P1 起，M3/M4）

| 模块 | 职责 | 依据 |
|---|---|---|
| `client/store.ts` | 定义列表/读写的客户端 RPC 封装 | 官方 client 面约定（`dsh.client` 声明） |
| `client/editor/` | settings section 或侧栏页：列表 + 表单编辑（节点排序、prompts 多行、模型下拉、技能/工具多选） | 参照 ui-plugin-manager / ui-cordis 模式 |
| `client/run-node/` | `ConversationNodeDefinition` keyed renderer：节点链 + 状态徽章，订阅 `workflow/*` | 官方 dsh-client-ui-workflow-run 先例 |
| `client/runner-view/` | 运行入口：选流水线 + 初始输入 + 运行按钮（目标=当前会话） | — |

- M4 增量：run-node 徽章接入耗时/token（从 `workflow/agent-start/end` 时间差 + session 统计聚合）。

## Agent 编排约定（执行时谁做什么）

- **主 agent**：架构与口径守门人；负责 runner/compiler 核心实现与全部基准回跑；每里程碑收尾回写 plan + HANDOFF。
- **可并行的子任务**（互相无文件依赖，可派子 agent）：schema+store 与 compiler 单测 fixtures 制作；client 编辑器骨架与 run-node 渲染（M3 起且 host API 冻结后）；README/文档撰写（M5）。
- **禁止并行**：ir/compiler/runner 三者的语义改动（共享既定口径，改一个必须重跑 B1-B3）。
