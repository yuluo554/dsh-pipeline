# 模块详设（plan/03）

> 目录约定：`src/`（host 半）、`client/`（web 半，P1 起）、`data/`（fixtures，见 plan/04）。签名在实现时可微调，改动需回写本文件。

## host 半模块

### schema.ts — 定义校验（FR-1）
```ts
export interface PipelineDef {
  name: string; description: string
  nodes: PipelineNode[]
  options?: { maxAgentsPerNode?: number; defaultFailurePolicy?: 'abort'|'skip' }
}
export interface PipelineNode {
  id: string; label?: string
  prompts: string[]                       // ≥1 条，节点内按序投递
  model?: { provider?: string; model?: string; reasoningEffort?: string }
  skills?: string[]; tools?: { allow?: string[]; deny?: string[] }
  dependsOn?: string[]                    // 缺省 = 线性串接前一个
  outputSchema?: JSONSchema; failurePolicy?: 'abort'|'skip'; retry?: number
}
export function validateDef(raw: unknown): { ok: true; def: PipelineDef } | { ok: false; errors: DefError[] }
```
- 测试点：合法/非法矩阵（B2 基准）；错误信息可读（含 JSON 指针路径）。

### ir.ts — 规范化中间表示（对应方法论"统一中间表示"）
- 输入 `PipelineDef` → 输出有序执行图（线性化节点序列 + 每节点解析后的模板变量依赖表）。
- 规则优先、确定性：拓扑排序（Kahn）、环检测、未知 `{{var}}` 静态拒绝、`dependsOn` 显式覆盖隐式串接。
- M2 回写（2026-09-27）：IRNode 增 `failurePolicy`（节点值 ?? options.defaultFailurePolicy ?? 'abort'）、
  `retry`、`skills`（声明的技能名）三字段；模板引用 skip 策略节点 → `IR_SKIP_REFERENCE` 拒绝
  （dependsOn 指向 skip 节点合法）；`totalAgentCalls` = Σ prompts.length × (1 + retry)（retry 感知上界）；
  特性闸门收敛到引擎确实路由不了的三项：tools / reasoningEffort / options.maxAgentsPerNode。
- 测试点：环依赖/自依赖/重复 id/未知变量 → 明确错误；线性化顺序稳定（同输入同输出）。

### compiler.ts — IR → 脚本（FR-2，核心资产）
- `compile(ir: PipelineIR): string` —— 生成普通 JS workflow 脚本；模板注入用 JSON 安全拼接（`JSON.stringify` 值插值），**禁止 eval/Function**。
- 节点内多 prompt：`for` 循环顺序 `await agent({...})`，前次输出按变量名并入下一次 prompt 上下文。
- M2 回写（2026-09-27）：签名 `compileScript(ir, skills?: ResolvedSkills)`——ResolvedSkills = 节点 id → 已渲染技能块列表；
  失败策略编译进脚本（abort+retry0 = M1 形状不变；skip/retry = 整节点 attempt 循环骨架，耗尽按策略收场）；
  技能块前置到该节点每条 prompt（每次 agent() = 新子会话）；头第二行 = `N nodes, M agent calls max; policies: …`（冻结）。
- 测试点：B1 快照基准（固定 fixtures → 固定脚本字符串）；生成脚本过语法检查（`new Function` 仅用于语法校验，不执行——或用 acorn 解析）。

### runner.ts — 唯一官方 API 触点（FR-3/6/8/12）
```ts
export interface RunDeps { engine: WorkflowEngine; caps: SubagentCapabilities; parent: Agent; providerName: string; signal?: AbortSignal }
export interface RunOutcome { value: unknown; stopReason: 'completed'|'cancelled'|'error'; error?: string; agentsStarted: number }
export async function runPipeline(deps: RunDeps, def: PipelineDef, input: string): Promise<RunOutcome>
```
- 职责：能力探测（caps 缺 flag → 可读报错，绝不静默）→ `engine.start({ script, meta, args, subagentProvider: providerName, maxTotalAgents, parent, signal })` → `await run.result` → 失败策略执行（abort 直接上抛；skip 映射节点输出为 null 并继续；retry 在脚本内循环）→ 统一 `RunOutcome`。
- M1 实装：abort 语义编译进脚本（agent() 返 null → 节点抛错）；skip/retry 进编译器 = M2。
- 失败策略、retry 循环都**编译进脚本**，runner 只组装——保证与引擎语义一致。
- M2 回写（2026-09-27）：skills 解析进 runner——engine.start 前 `ctx.skills.get(name)` 逐个解析（RunDeps 增可选 `skills` 解析器；ctx.skills 由 entry 惰性传入），`renderSkillContent`（dsh-skill 0.1.5-rc.1）渲染后经 ResolvedSkills 交给编译器；缺注册表/缺技能/技能畸形三类 `SKILL_MISSING` / `CAPABILITY_MISSING` fail-loud；`maxTotalAgents` = Σ prompts × (1+retry)。
- M1 回写（2026-09-27）：入参收 `def`（校验后的定义）而非 `name`——store 查找留在 entry，runner 保持无 fs 依赖、可离线测；`RunOpts` 暂缺（无必要字段，后续需要再加）。`providerName` 进 RunDeps：runner 用它把 run 钉在被探测能力的同一 provider 上（`subagentProvider`），探测与实际路由永不漂移。

### store.ts — 定义存取（FR-1）
- `listDefs(ctx) / loadDef(ctx, name) / saveDef(ctx, def) / readRawDef(ctx, name)`，路径 `工作区/.dsh/pipelines/<name>.json`。
- M1 回写（2026-09-27）：原子替换由 fs seam 自身提供（dsh-fs-local `writeText` = 临时文件 + 原子发布 + 递归建父目录，实测源码），不再自写 temp+rename；`readRawDef` 为 `/pipeline show` 服务；名字先过 schema 校验器语法（防路径穿越）再触盘。

### entry.ts — 入口注册（FR-4/5）
- `/pipeline list|show|run|help` 命令（`ctx.commands`，不经模型轮次；run 的 input = 名字后余文）。
- `pipeline` 模型工具（`ctx.tools.register(defineTool(...))`）：参数 `{ name, input }`，返回格式化摘要（每节点输出截 2000 字符）；描述声明"固定流程重复任务"场景（供模型路由）。
- 全部注册为 Cordis effect，随插件卸载撤销。
- M1 回写（2026-09-27）：插件配置唯一旋钮 `provider`（默认 `spawn`，= 引擎默认 subagent provider）；provider 不存在时报可读错误并列出可用项。

## M1 实现回写（2026-09-27，冻结口径的落点）

- **模板变量词表**（IR 规范化的一部分）：`{{input}}`（运行输入）/ `{{<nodeId>}}`（该节点末条 prompt 输出）/ `{{prev}}`（同节点上一条 prompt 输出，首 prompt 引用即报错）；模板引用同时生成依赖边（引用下游节点合法——排序由拓扑决定）；畸形 `{{…}}` 一律 `IR_UNKNOWN_VARIABLE` 拒绝。节点 id 语法 `/^[A-Za-z0-9][A-Za-z0-9_-]*$/`，`input`/`prev` 保留。
- **编译脚本骨架**：`const out = {}` → 每节点 `phase("<label>");` + `{ const __pN = await agent(<expr>, { label, provider?, model?, schema? }); if null throw }` + `out["<id>"] = __pN` → `return { nodes: out };`；agent 选项字段序冻结 label→provider→model→schema；多 prompt 节点 label 追加 ` #k`。meta.phases = 各节点 title。
- **M1 特性闸门（ir.ts）**：`skills/tools/failurePolicy≠abort/retry>0/options.*/reasoningEffort` → `IR_UNSUPPORTED_FEATURE`（可读、指名节点）。理由：0.1.5-rc.1 引擎 agent() 仅支持 label/phase/schema/provider/model（effort/isolation/agentType 显式拒绝，无 toolFilter 通路），路由不了就明说，不静默忽略。
- **B1-B3 基准与 mock**：`src/bench.ts`（runB1/B2/B3，data/ 内置随包发布）+ `scripts/bench.js`（指标表，`pnpm bench`）+ `src/mock-engine.ts`（离线引擎孪生，语义逐条对照 worker.cjs 实测；断言对象 = agent() 调用参数序列 + 事件序）。
- **装载面**：插件 `inject = ['tools','workflowEngine','subagents','commands','fs']`；bundle patch（cordis.patch.yml）新增按 id 覆盖行，启用 web profile 默认禁用的 `workflow-worker-thread`（见 plan/06 决策记录）。
- **防失控上限**：`maxTotalAgents = Σ prompts.length`（脚本恰含每 prompt 一次 agent() 调用，精确上界）。

## Agent 编排约定（执行时谁做什么）

- **主 agent**：架构与口径守门人；负责 runner/compiler 核心实现与全部基准回跑；每里程碑收尾回写 plan + HANDOFF。
- **可并行的子任务**（互相无文件依赖，可派子 agent）：schema+store 与 compiler 单测 fixtures 制作；client 编辑器骨架与 run-node 渲染（M3 起且 host API 冻结后）；README/文档撰写（M5）。
- **禁止并行**：ir/compiler/runner 三者的语义改动（共享既定口径，改一个必须重跑 B1-B3）。
