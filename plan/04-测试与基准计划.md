# 测试与基准计划（plan/04）—— 数据先行

> 方法论对应：阶段 1"数据先行"与阶段 5"内置基准评测"。本项目的"数据"= 流水线定义 fixtures + 编译快照真值 + mock engine 行为脚本；所有基准**零 API 依赖可重复**。

## data/ 目录与台账

```
data/
├── pipelines/          # 流水线定义 fixtures（合法样例）
│   ├── single-node.json          # 最小：1 节点 1 prompt
│   ├── three-node-two-models.json # M1 演示原型：大纲(cheap)→复查→成文(reasoner)
│   ├── multi-prompt-node.json    # 节点内 3 条 prompt
│   ├── skills-and-tools.json     # skills 注入 + tools.deny
│   ├── depends-explicit.json     # 显式 dependsOn（DAG 而非线性）
│   ├── retry-skip.json           # retry:n + skip 策略
│   └── output-schema.json        # 节点结构化输出
├── invalid/            # 非法定义（环依赖/空prompt/未知变量/重复id/坏dependsOn…）
└── snapshots/          # 编译快照真值（期望脚本字符串，由首版编译器生成后人工审定冻结）
```

`data/README.md` 登记每份 fixture 的来源（自制）与用途；快照文件头部注明生成时编译器版本，**人工审定后才算真值**。

## 真值语义（一次定清，写进生成器/快照模块注释；改动=口径变更须走 plan/06）

- **编译快照真值**：fixtures + 规范化规则 → 期望脚本字符串。序列化约定固定（2 空格缩进、属性序 = IR 字段序）；空格/顺序变更视为口径变更。
- **mock engine 真值**：mock `WorkflowEngine` 按"行为脚本"回放——节点执行序、`agent()` 参数快照（label/prompt/agentOptions/toolFilter）、取消注入点、失败注入点。断言对象 = `agent()` 调用参数序列，而非模型输出。
- **互斥坑登记**（当场记录，格式：场景 / 错误行为 / 正确语义）：先登记两条已知——① 显式 `dependsOn` 与隐式串接并存时以显式为准；② 模板变量引用失败 skip 的上游节点时编译期拒绝（引用 null 是语义错误，不是空串）——② 已于 M2 随 skip 落地启用（`IR_SKIP_REFERENCE`）。
